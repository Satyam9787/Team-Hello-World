    From kernel event to verdict in three steps

    Only a small probe runs on the host. Decisions are made on the backend, so rules change in one place.

    1

    Probe observes

    A kernel probe captures each new process with its PID, parent, user, binary path, and arguments.

    2

    Record is sent

    The record is streamed to the Prahari backend over an encrypted connection in near real time.

    3

    Backend decides

    Policy rules and reputation checks return a verdict: safe, suspicious, or blocked, with the reason.

    Unknown binaries do not stay hidden

    When an unrecognised file starts running in the background, Prahari captures its path, hash and behaviour, blocks it, and raises an alert.

    • Executes from /tmp or shared memory
    • Disguises itself as a kernel thread
    • Rewrites its own code while running
